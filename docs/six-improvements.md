# Six Relay improvements

Each feature was committed separately, with follow-up integration fixes.

- **Memory typing:** selected input is restored after macOS activates the menu-bar window. Drafts survive state refreshes. Tested by typing into the native Electron Memory page across a refresh, without saving any personal memory. A user's own keyboard/installed-window confirmation remains useful because the original failure was intermittent.
- **Backdrop:** General → Backdrop intensity and design. The slider blends the actual native macOS visual-effect window; it controls opacity, not a configurable blur radius. Choose a PNG/JPEG/WebP under 12 MB; Relay decodes/resizes it into one app-owned local PNG. No HTML, remote URL or online image service. Remove image deletes only this app-owned copy. The effect is click-through and hides with the reactor. Native opacity/image/hide lifecycle and choose/remove UI verified.
- **Work modes:** General → Work mode → Actions for this mode. Save up to eight app names, optionally select a saved routine, and choose Keep or Quiet Relay phone-completion notifications. Select a mode to apply it, or say “set work mode to coding.” Routine execution uses the normal request queue and approvals. This does not change system Do Not Disturb or disable security warnings. The previous notification preference is restored when leaving a quiet mode. Configure apps/routines yourself; none are assumed.
- **Scheduled calls:** Calls → Scheduled check-ins. By default a schedule creates a review. A separate, initially unchecked authorization lets that specific schedule dial the saved owner number automatically, for its saved purpose and the current duration/provider/voice. Changes to number, duration, provider or voice require recreating authorization; normal quiet hours, private mode, daily budgets and active-call protection still apply. Late occurrences are skipped, not caught up. Relay must be running and awake. Remove a schedule to stop it. Saving a schedule never dials. Tests used fake providers only; no real calls placed. Provider account/credits still required.
- **Wake and follow-up:** wake handoff extends through revised partial transcripts, preserving commands spoken immediately after the phrase. Bare-wake acknowledgement uses the fast speech path. Claps require a short first impulse rather than sustained sound; General offers a threshold slider. “Yes, open Notes” strips the conversational prefix in follow-up. Room noise and hardware microphones require a real trial; this is not a guaranteed sound classifier.
- **Shared hands:** General → Shared hand control → 2, 4 or 6 tracked hands. Each cursor has a different color. Six hands can support three people presenting both hands; this does not identify or authenticate people. A bounded tracking algorithm keeps same-handed detections in stable slots, reserves temporarily missing slots, and resets old grabs before a new hand reuses one. Several Jarvis panels can be moved independently. Ordinary app windows and browser tabs share the one system pointer, so only one external drag occurs at a time. A fist must start on a native-approved title/tab region. Movement waits for native acknowledgement; rejection is silent and interrupted/restarted camera sessions release ownership. Accessibility permission is required. Camera/model inference with real people, crossings and real Chrome/Firefox tabs is not verified by simulated-frame tests.

All configuration stays local except actual calls through the selected calling provider. No microphone or camera recording was added, and no new package/service was installed.
