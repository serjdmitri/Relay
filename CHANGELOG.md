# Changelog

## 0.34.0

Built by the cloud session; unit-tested only. **None of it has run on a real Mac**: if Relay does not open, run `npm start` in the repo and send the first error. The experimental features are all off by default: turn them on one at a time in Settings > Doctor > Experimental, and run Doctor first.

- **Faster answers** (General > Faster answers, on by default): Claude starts with extended thinking off, Codex runs with low reasoning effort, independent tool calls are made together, and Relay no longer re-checks (read back or screenshot) after every action, only when the result is unclear or hard to undo. The speed-up is not measured: try the same requests with the switch on and off, with "Show usage after each ask" on.
- **Fewer tools per request.** Rarely used tool groups are hidden behind two small tools (load more tools, use a tool); Doctor logs when Claude asks for one.
- **Command Relay by text, with a queue while the Mac sleeps (experimental).** Text your own thread; pairing needs a one-time code and only your own messages count. Texts sent while the Mac slept run in order on wake and a later text can cancel an earlier one. Risky requests ask on the Mac and by text, first answer wins; you choose what happens if nobody answers. Held texts older than a day are listed in Doctor with Run now and Drop. Not tried: reading `chat.db`, sending replies through Messages.
- **Plugins (experimental).** Paste a GitHub link or a folder: Relay shows the exact commit and every permission in plain words and installs only after you approve. Each plugin runs as its own process, in a macOS sandbox where one is available; plugins that can change things or run commands ask before every call. Not tried: the sandbox and the approval dialog.
- **Live panels (experimental).** CPU, memory, battery, network, disk or what Relay is working on, as small floating panels; a plugin can offer one; Claude can build one from a small web page that runs in an isolated frame, gets only the numbers it declares and reaches only hosts you approve. Not tried: the floating windows.
- **Ask my notes (experimental).** Indexes folders you choose and finds passages by meaning ("car" finds "vehicle"). Files named like passwords or keys and hidden folders are never read. The Swift embedding helper was never compiled; if it fails to build, a stand-in is packed and search falls back to words (Doctor says so). The 0.55 similarity cutoff is a first guess.
- **Smarter memory** is now shown in Settings (its switch was hidden by mistake).
- **Speak up on its own (experimental).** Battery, upcoming meetings and long jobs: quiet banner (default), always quiet, or speak anything important, with quiet hours. Not built: "a watched folder changed" and plugin-sent events.
- **Offline mode.** With no internet, plain questions go to your local Ollama model; anything that needs the Mac or the web says it needs the internet.
- **Recent menu:** opens only from its tab (half as thick, three times as tall, adjustable delay), and the panel and its curved flares are one liquid-glass shape joined to the screen edge.
- **Fixed before release:** a startup crash (the text-command switch was defined in one function and called from another).

## 0.33.0

- **No more rough 3D guesses.** A model made from one photo is a guess at every hidden side, so it is no longer shown by default. A real ready-made model still opens as a hologram, and so do the sharp generators when a Hugging Face token is set. Otherwise "show me ... in 3D" shows a card with the clearest real pictures it found and YouTube searches for an overview, reviews and a close-up/teardown (plus links for more pictures and all videos). If the model finds specific video links while researching it adds them with a second card. The old behavior (photo models from the fast generator, shapes stand-ins) comes back with `settings.models3dApprox: true`. The YouTube links are searches, not hand-picked videos, and the pictures depend on what Wikimedia has: untested against the live services from the cloud.
- **Cut sections turn with the model.** When you cut into a hologram and rotate it, the cut plane used to stay fixed to the screen, so the section changed as you turned the piece. The plane is now fixed to the model when you turn the cut on (or change its axis) and rotates with it. Checked in a headless page: after a 90 degree turn the plane normal followed the model and the offset stayed the same.
- **Homework helper.** Select an assignment (or open it on screen) and say one of these. Relay reads it on the Mac, has the model do the long work on a stronger model, and saves the result in Documents/Relay Homework (a Word file, PDF or plain text, your choice; code as a folder of files shown in Finder). The spoken reply is one or two sentences. Nothing is ever overwritten (a taken name gets " (2)").
  - "Help me with this assignment": the requirements, rubric items, likely hard parts and a plan.
  - "Outline this essay" (or "outline an essay about ..."): thesis options and an outline with where the evidence goes.
  - "Write a draft" / "write an essay about ..." (add "in my voice"): a complete draft in your voice, with [square brackets] where a detail should be your own. Say "use this as my writing sample" with some of your writing selected, or paste a sample and describe your voice in Settings, so it sounds like you. The default voice description is the one you gave me: conversational but clear, concrete examples, SAT-level words, no em dashes, no stock AI phrases.
  - "Give me a template for this assignment" / "starter code": the project skeleton with function signatures, docstrings, TODO hints and a few tests, without the working logic.
  - "Do this assignment" / "complete the whole coding assignment": the complete solution (a working project with README and tests, a full draft, or every step of a problem), with a short "How it works" section so you can explain it in your own words.
  - "Walk me through this problem": every step with its reason, then one practice problem. "Check my answer": says whether it is right and points at the first wrong step with a hint instead of the answer. "Give me feedback on my essay" (also "proofread my paper"): strengths, then weaknesses in order (thesis, evidence, structure, analysis, comparison, word choice with stronger SAT-level words), quoting your lines.
  - Settings > General > Homework helper: save as Word, PDF or text; your voice description and writing sample; "Allow whole solutions" (off: "do this assignment" gives a template or outline instead); "Explain what it made".
  - The assignment text is passed to the model as material, never as instructions. Use it only where your teacher allows AI help.
  - Not tried on a real Mac: the Word file is made with the Mac's own `textutil` (falls back to PDF, then text if it fails), and the PDF with the same hidden window as the workshop handouts.
- **Answers stay on screen until you dismiss them.** Settings > General > "Keep answers on screen until I dismiss them" (on). An answer, and the picture card that comes with it, now stays up until you say "ok" (also "okay", "thanks", "got it", "close", "that's all"), press Esc, or ask the next thing. Before, the answer went after a few seconds and the card after 30. When an answer is up and you asked it by voice, Relay keeps listening for up to 25 seconds so "ok" can be heard (after that, "Hey Jarvis, ok" or Esc still work). Saying "ok" closes it silently: no reply, no sound. Short replies to quick commands ("Paused", "Volume 40%") still go by themselves, answers asked from the phone or by a schedule are not held, and an answer you walked away from closes after ten minutes. While a quiz or a checklist is running, "ok" and "got it" keep their normal meaning there.

## 0.32.0

- **Codex as the backup when Claude runs out of usage.** Account > "Backup when Claude runs out": sign in to Codex with your ChatGPT account (the button runs Codex's own `codex login`, so your plan is used and no API key is; Relay never sees or stores the login, and a Codex that is signed in with a key does not count). When a request comes back from Claude stopped by its usage limit, Relay notes when the limit resets and finishes that same request with Codex, with no message, no sound and no question: you just get the answer. Later requests go straight to Codex until the reset time, then Claude is tried again by the next request; if it is still limited, that request is finished by Codex and the wait starts over. The reset time is kept across restarts.
  - Codex gets Relay's own tools through the same local tool server Claude uses (so confirmations, the home-folder switch and the never-delete rules apply the same way), plus Relay's usual context. Its own tools are held to a read-only sandbox with no saved session and without your Codex config, and a run that tries to change files is stopped.
  - If Codex is out of usage too, one sentence says so and when Claude should be back. If Codex is not installed or signed in, Relay behaves as before and shows Claude's own message. Switch: Account > "Switch to Codex when Claude runs out" (on).
  - The usage line under an answer (if you have it on) says "codex" for those answers, and History keeps which model answered. Claude's limit no longer triggers a pointless retry on a stronger Claude model first.
  - Tested with a fake `codex` program and a fake Claude (583 tests). **Not run against a real Codex sign-in**: I could not sign in here, so how Codex handles Relay's tools (its MCP connection, whether it asks to approve each one in this mode) is the part most likely to need a fix on your Mac. Install with `npm install -g @openai/codex`, sign in on the Account page, then ask for something while Claude is rate limited, or test it by turning off Claude's access.
